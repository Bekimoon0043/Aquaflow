AquaFlow Step 2 - Canonical Schema and Runtime Contract
=======================================================

Purpose
-------
Define the canonical data model that all future layers must share:
- React editor
- Python API/orchestrator
- Rust runtime core
- Show compiler
- Deployment builder
- Simulation service

Design rules
------------
1. The current .aqua payload remains supported during migration.
2. Live runtime must consume compiled canonical payloads, not ad-hoc editor state.
3. Canonical schemas live under shared/lux-schema.
4. Python adapters translate current editor/backend payloads <-> canonical package format.
5. Runtime transport/contracts live in backend/contracts for immediate integration.

Deliverables added in this step
-------------------------------
- Expanded JSON schema set for clips, tracks, nodes, safety rules, deployment bundles,
  runtime sessions, telemetry frames, and calibration profiles.
- Canonical package examples under shared/lux-schema/examples.
- backend/schema_adapter.py for current AquaFlow payload conversion.
- backend/contracts/runtime_contract.py for Pydantic runtime message contracts.
- backend/validate_step2_contracts.py for local validation and round-trip testing.

Migration impact
----------------
No existing frontend/backend runtime path was removed.
This step is additive and safe for the current prototype.
