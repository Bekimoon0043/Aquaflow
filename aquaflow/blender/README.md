# AquaFlow Studio → Blender addon

Imports AquaFlow `.aqua` / `.aquashow` / `.aquapkg` projects into editable Blender scenes with native Mantaflow liquid, Cycles water, animated show lighting, site geometry and cameras. Per-fixture timeline tracks, pump/valve/RGB channels, packaged site models, and rotating basket outlets are supported.

**Version:** 0.4.0. Tested with Blender 3.3.21; no third-party Blender addon is required. A Blender 5 compositor compatibility path is included, but Blender 5 has not been runtime-tested in this workspace.

## Install

1. Open **Edit → Preferences → Add-ons**.
2. Choose **Install from disk** (or **Install…** in older Blender) and select `aquaflow_studio_blender.zip`.
3. Enable **AquaFlow Studio · Fountain to Blender**.
4. Open **File → Import → AquaFlow Fountain (.aqua / .aquashow)**, or **3D View → N → AquaFlow**.

The source lives in `aquaflow_studio/`; the ZIP contains that folder at its root. Twelve original generated GLB equipment models are included and preferred for nozzles, lights, pumps, valves, manifolds, lasers and flame burners, with procedural assemblies retained as fallbacks. These original models require no third-party asset license.

No AquaTiq/engon addon is required. The addon can directly use user-supplied `.blend` water effects and materials from v1.1.1 or a v2 `.paq` pack; these third-party files stay external and are not included in the ZIP. Each PC needs the asset files and the appropriate license. Original clear/aerated mask and normal sequences generated by `procedural_textures.py` are included inside the addon folder as a fallback. Blender does not pack image sequences, so these original files remain in the installed addon directory; supplied third-party assets always remain external.

## Choose the right water mode

### Design proxies

Imports the entire site immediately with animated ballistic jets, bells, cascades, mist, water materials and show lighting. Use this for layout, camera selection and lighting review.

**Proxy jets are not a fluid simulation.** They use enlarged visual radii where needed for readability and preserve the design jet height.

### Hero nozzle · native liquid

Creates a local Mantaflow domain around one nozzle. Other nozzles can remain clearly labeled proxies. Enter a fixture ID in **Hero fixture ID**, or leave it blank to select the highest design jet.

Use this for real fluid shots. Start with a few frames and 32–64 divisions to test the setup, then tighten the domain and increase resolution.

### Whole site · native liquid

Creates one domain for the pool and all non-mist nozzles. This is a starting layout, not an automatic production-quality simulation. Large sites with small outlets can require thousands of divisions; read the import report before baking.

## Import and bake workflow

1. Save your AquaFlow project as `.aqua` or `.aquashow`.
2. Import it into Blender. The addon creates a **new scene** and does not clear your existing scene.
3. Check the imported cameras and the `AQUAFLOW_IMPORT_REPORT.json` text block.
4. For a native mode, set a short **Last frame** for the first test. `0` means the complete show.
5. Select a cache root with enough free disk space. Paths are made absolute when the domain is created so later `.blend` saves do not break them.
6. Click **Bake Native Liquid**. The operator bakes data, mesh and secondary particles, verifies that a readable liquid mesh exists, then enables the domain for rendering.
7. Scrub to a developed frame and press **F12**.

The domain is intentionally hidden from rendering until its bake succeeds. Source JSON and the report are embedded as Blender text blocks.

## Lighting and render settings

- Cycles, CPU compatibility default; choose your supported GPU in Blender if available.
- Water IOR 1.333, transmission and depth absorption.
- Foam, spray and mist use separate materials rather than emissive clear water.
- Physical spot/area light sizes and beam angles.
- Luminous flux converted to approximate radiant watts; electrical fixture watts are not passed directly to Blender.
- External IES profiles are used when a fixture contains a valid referenced path.
- Legacy tracks and flat fixture clips are keyframed, including RGBW and fades.
- Pump ramps, valve strokes, pipe-volume filling and shared multi-outlet flow.
- Animated volumetric laser beams and flame/heat/smoke visualization proxies. These are not certified laser-safety, combustion or physical effects simulations.
- Editable nozzle, pump, valve, filter, pipe and luminaire assemblies with stainless steel, brass, bronze, PVC, HDPE, EPDM, glass and architectural material presets.
- Colored emissive luminaire lenses and shallow-water volume scattering.
- Continuous basin collision, rim overflow and external runoff drains.
- AgX where available, Filmic on Blender 3.3, adaptive sampling, denoising, light tree and motion blur.
- Optional architectural reflection lighting. These named area lights are art-directed environment fill, not measured fixture photometry; disable them when using a calibrated venue/HDRI.

Read `../docs/BLENDER-WATER-LIGHTING.md` and `../docs/FOUNTAIN-COMPONENTS.md` for the research, formulas, component behavior, materials, limitations and production guidance.

## Command line

Run from the repository root, substituting your Blender executable:

```bash
blender -b --python-exit-code 1 --python aquaflow/blender/render_aquaflow.py -- \
  --input aquaflow/samples/lebu-pilot/Lebu_Fountain_Pilot.aqua \
  --output .tmp/blender/lebu.blend \
  --render .tmp/blender/lebu.png \
  --scope PROXIES --camera-id center-feature --samples 64
```

Native hero bake and a developed-frame render:

```bash
blender -b --python-exit-code 1 --python aquaflow/blender/render_aquaflow.py -- \
  --input fountain.aqua --output hero.blend --render hero.png \
  --scope HERO --hero-id lebu-center-hero --resolution 256 \
  --frame-end 48 --render-frame 48 --bake --samples 128
```

Options include `--width`, `--height`, `--exposure`, `--light-multiplier`, `--no-proxies` and `--no-secondary-particles`.

## Files

- `aquaflow_studio/core.py` — pure schema, coordinate, hydraulic and simulation-plan conversion.
- `aquaflow_studio/animation.py` — pure legacy/flat timeline evaluation.
- `aquaflow_studio/scene_builder.py` — Blender geometry, domains, particles, cameras, lighting and bake validation.
- `aquaflow_studio/materials.py` — Cycles materials.
- `aquaflow_studio/operators.py`, `panel.py`, `properties.py` — Blender UI.
- `render_aquaflow.py` — headless import/bake/render entry point.
- `tests/` — dependency-free Python tests (Blender is not needed for these).

Run pure tests from the repository root:

```bash
python -m pytest aquaflow/blender/tests -q
```

## Current limitations

- Main basin and site surfaces are imported; multi-basin holes, custom venue meshes and detailed manufacturer nozzle geometry need more work.
- Fan/crown/bell fixtures use representative shared-flow outlets, not manufacturer-exact outlet geometry. Hydraulic response is a lightweight boundary-condition model, not AquaFlow's full network solver.
- Air-shooter/digital-curtain specialist state machines, moving machinery, LDT conversion and gobo/video projection are not yet reproduced by this version.
- Photometric values without manufacturer lumens/IES are estimates. RGBW in Cycles is an RGB lighting approximation, not spectral simulation.
- Native outlets keep their actual radius; unresolved nozzles remain labeled proxies rather than enlarged emitters that would add excessive water. Use roughly four or more voxels across the real outlet for a resolved production jet.
- A successful bake proves that native liquid was generated; it does not prove product-specific hydraulic accuracy or final artistic quality.
